# 卦安关系盘 1.0 冻结记录

冻结日期：2026-07-22
状态：正式冻结
适用入口：`/marriage`
核心实现：`src/lib/domain/relationshipInteractions.ts`、`src/components/MethodWorkspaces.tsx`

## 1. 产品定位

关系盘 1.0 是“关系结构初见”，以双方日柱为入口，观察沟通、分歧和协作中的传统结构关系。

它服务一次单人发起的双人关系查看：用户先看到三项生活观察和一条共同动作，再按需查看双方日柱、双向十神、五行阴阳与日支关系依据。它不是两份个人八字画像的并排展示，也不是现实关系质量或结果的判断工具。

## 2. 当前输入范围

- 本人：复用已经保存的出生资料；关系盘只读取计算所得日柱。
- 对方：仅输入出生日期。
- 关系类型：伴侣、家人、朋友、合作。
- 关系类型只改变场景翻译，不改变日柱和专业关系事实。

当前不收集对方姓名、性别、出生时辰或详细地址，不保存对方资料，也不创建关系数据库记录。

## 3. 当前使用的跨人事实

`buildPairInteractionFacts(firstChart, secondChart)`只建立以下事实：

1. 双方日柱、日主与日支；
2. 双方日干五行与阴阳；
3. 双方日干五行的客观生克方向；
4. “你看对方”的十神关系；
5. “对方看你”的十神关系；
6. 双方日支明确成立的同支、六合、六冲、六害、六破与刑。

关系观察卡必须引用跨人事实，不调用两人的个人八字观察卡、生肖配对、星座、隐藏人格模型或自定义匹配评分。

## 4. 双向十神的计算方向

- “你看对方”：把你的日干作为参照，计算对方日干相对你的十神。
- “对方看你”：把对方日干作为参照，计算你的日干相对对方的十神。

交换双方顺序后，两个十神方向和双方所在位置随之交换；水克火等客观五行关系本身不会因交换顺序而改变。

用户可见边界为：

> “你看对方”和“对方看你”，是把双方日干互相作为参照得到的结构观察，用来提示可能的互动顺序；它不代表双方在现实中固定承担某种角色，也不等于完整四柱合参。

十神在本版中是结构类比，不是现实角色证明。不得据此认定谁负责付出、接受、控制、服从或承担固定分工。

## 5. 日支关系支持范围

固定表支持：

- 同支；
- 六合；
- 六冲；
- 六害；
- 六破；
- 子卯相刑；
- 寅巳申、丑戌未中仅凭两个日支可以确认的“刑的一部分”；
- 辰、午、酉、亥自刑；
- 无直接命名关系。

同一对日支可以同时命中多个名称，例如巳申、寅亥和午午。所有明确成立的名称均保留，不设优先级，不让一个名称覆盖另一个名称，不计算综合吉凶。

用户可见边界为：

> 同一对日支可能同时出现多种传统关系名称。它们表示不同观察角度，不自动互相抵消，也不共同生成吉凶结论。

只有两个日支时不伪造三合、三会或完整三刑。六合不等于现实中必然融洽；冲、害、破、刑也不等于现实中必然冲突。

## 6. 三张关系卡分别回答什么

1. **你们怎样接上话**：用双向十神和日干五行观察双方可能先处理什么、怎样接住彼此，以及把自己的顺序当成默认顺序时可能出现的误解。
2. **分歧容易从哪里出现**：以日支关系为主要依据、双向日干为辅助线索，观察分歧可能从节奏、方向、隐含前提、执行松动或反复修正中的哪个位置出现。
3. **怎样把事一起做完**：用双向十神和日干五行给出一次性的分工尝试，同时明确该分工不是双方现实中的固定角色。

每张卡包含具体结论、触发场景、可用之处、过度风险、行动、主要依据、辅助线索和本卡边界。专业依据默认折叠在“为什么这样说”中。

## 7. 共同行动怎样产生

`buildRelationshipJointAction(cards)`从“分歧容易从哪里出现”卡片取得已生成的行动，并保存来源卡片 ID。

共同行动必须：

- 双方都能参与；
- 15 分钟内可以开始；
- 有明确完成条件；
- 不要求购买物品；
- 不涉及改运；
- 不代替婚姻、心理、法律或职业咨询。

没有有效关系卡时不生成共同行动。

## 8. 不确定性处理

- 没有本人保存资料时，先提示保存生辰，不生成关系观察。
- 没有对方出生日期时，不生成关系卡和共同行动，并直接提示缺少的资料。
- 关系盘 1.0 不使用双方出生时辰进行生活判断，不以默认时辰制造差异。
- 无直接日支命名关系时，只记录“无直接关系”，不推断相处自然顺畅或自然困难。
- 局部刑只显示当前可确认的部分，不补猜缺失条件。

统一页面说明：关系初见以双方日柱为观察入口，不代表完整合婚，也不判断关系结果；出生时辰不参与本次生活判断。

## 9. 安全边界

关系盘不得输出或暗示：

- 关系好坏、匹配度或婚姻结果；
- 是否应该结婚、分手或继续合作；
- 忠诚、第三者、生育或家庭暴力风险判断；
- 谁旺谁、谁克谁的现实价值判断；
- 心理诊断；
- 宿命、保证或恐惧诱导；
- 医疗、法律、投资、职业或婚姻专业决策。

如现实关系涉及暴力、胁迫、自伤或安全风险，应优先寻求现实支持，不得用日柱或十神解释风险。

## 10. 已通过的测试和验证

专项测试：`tests/relationship-interactions.test.ts`。

覆盖内容包括：

- 双方日柱与双向十神方向；
- 交换顺序后的事实稳定性和方向翻转；
- 日干五行、阴阳关系；
- 同支、六合、六冲、六害、六破、刑、局部刑、自刑与无直接关系；
- 巳申、午午等多重日支关系；
- 不伪造三合、三会和完整三刑；
- 三张卡的跨人证据、主要依据和辅助线索；
- 共同行动来源；
- 资料不足停止输出；
- 四种关系类型不改变专业事实；
- 禁止词及不依赖个人八字观察卡；
- 用户可见的日柱、双向十神和多重日支关系边界。

确定性矩阵包含 32 组关系样本，覆盖相同日主、同五行不同阴阳、生克、相同日柱、顺序交换、只改变一方日期、四种关系类型、海外时区和历法边界。

正式冻结验证：

- `npm run test`：31 个测试文件、225 项通过；
- `npm run typecheck`：通过；
- `npm run build`：通过；
- 构建脚本在非 Vercel 生产环境明确跳过 Neon 同步，没有修改生产数据库。

## 11. 当前明确没有实现的能力

- 完整四柱关系合参；
- 时柱、月柱、年柱关系；
- 身强身弱、格局、喜用神、纳音、神煞、大运或流年关系；
- 关系评分、婚姻预测或结果判断；
- 多人物保存、关系历史或并排比较；
- 关系数据库模型；
- 付费关系报告；
- 导出分享；
- AI 自由生成关系解读；
- 关系簇差异算法。

## 12. 已知 P1

这些问题不阻断单次关系初见，本轮只记录，不继续开发：

1. 尚未统计用户可见关系文案的完全重复率；
2. 尚未统计高相似关系卡组合；
3. 十种十神可能对应有限数量的互动语言模板；
4. “怎样把事情一起做完”可能出现通用协作建议；
5. 四种关系类型可能主要改变场景翻译；
6. 多重日支关系可能增加小白理解负担；
7. 同一家人连续查看多份关系盘时可能识别模板；
8. 行动建议重复度尚未量化；
9. 只使用日柱，不能宣传为完整四柱深度合参；
10. 当前不证明每段关系都有独特描述。

关系盘 1.0 的已验证价值是单次关系初见，不是高度个性化或多人连续比较。

## 13. P1 重新启动的触发条件

只有准备开发以下任一能力时，才重新打开上述 P1：

- 保存多名亲友；
- 多段关系并排比较；
- 家庭关系连续查看；
- 关系历史；
- 付费关系报告；
- 对外宣传“深度合参”；
- 把关系观察卡用于重要现实决策；
- 导出多人关系报告。

重新启动时必须完成关系簇测试，至少统计：

- 用户可见三卡完全重复率；
- 高相似率；
- 行动重复率；
- 同一家人连续查看风险；
- 交换双方后的用户可感知差异；
- 不同关系类型是否只替换场景名词。

在触发条件出现前，不提前扩写文案、行动或理论。

## 14. 冻结后允许修改的范围

冻结后只允许修复：

- 双方日柱计算错误；
- 双向十神方向错误；
- 日支关系计算错误；
- 证据与结论错位；
- 资料不足仍输出结论；
- 高风险、宿命或婚姻结果判断；
- 页面阻断性故障；
- 构建、类型或安全回归问题。

不得因为想增加文案、提高独特度、让时柱制造差异、增加传统关系、降低模板感或精修视觉而重新打开关系盘 1.0。

## 15. 禁止宣传的产品能力

当前关系盘不得宣传为：

- 完整合婚；
- 完整四柱合参；
- 高度个性化关系分析；
- 婚姻预测；
- 关系匹配度；
- 关系结果判断；
- 谁旺谁、谁克谁；
- 判断是否适合结婚或合作；
- 每段关系都有独特命理解读。

唯一允许的定位是：

> 以双方日柱为入口，观察沟通、分歧和协作中的传统结构关系。

冻结的含义是接受“单次关系初见可用、多人连续查看存在尚未量化的模板风险”这一 1.0 边界，不等于宣称关系分析已经高度个性化。
